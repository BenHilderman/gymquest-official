# v4.3 acceptance audit checklist

Maps every locked-spec item from `docs/v4.3-extras-locked.md` Section 6 to a
specific on-device acceptance gate. Walk top-to-bottom on a real iPhone with
Wi-Fi + Photos access enabled and the v4.3 build installed.

## How to enter the audit fast

```bash
xcodebuild -project GymQuest.xcodeproj -scheme GymQuest_iOS \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  -derivedDataPath build_smoke build

xcrun simctl install booted \
  build_smoke/Build/Products/Debug-iphonesimulator/GymQuest.app

xcrun simctl launch booted com.colift.app -UITesting-V43Audit
```

The `-UITesting-V43Audit` flag flips `FeatureFlags.devSkipAuth` true for the
launch only, which:
- skips the login screen
- creates / re-fetches the `dev@liftai.app` `UserProfile` and marks it
  authenticated
- lands directly on the default tab

Add real friend / squad / crew rows manually to exercise the data-rich
surfaces (Squad Moments, Crew Moments, Crews header, Slot 2 chat preview).

## Real-device-only gates

These can't be verified in the simulator and need an actual iPhone:

- **Item E `in it · ...` while training** — start a workout, then open
  Profile mid-set; the line should update to active-workout state.
- **Item B throwback library photo** — the date-filtered picker reads from
  the device's actual Photos library; you need a phone with photos taken
  on the same date as a saved Workout to see real candidates.
- **PR ring buffer + slow-mo PR replay** — front camera capture during
  a workout, snapshot fires on PR, exporter renders portrait HEVC mp4 at
  9:16. *(`PRRingBufferRecorder.swift` + `ProofVideoExporter.swift`)*
- **Strava / Whoop / Apple Health integrations** — out-of-scope but the
  paths should at least open without crashing.

## Reporting issues

If a checklist item fails, file under `docs/audit-failures-<date>.md` with:
- spec item number
- expected behavior
- observed behavior
- screenshot path
- file:line reference from the checklist
